## 项目精简重构（DockerImgAutoBuildAndPush）

将原三工作流混合结构重构为「两条独立流水线 + 两个 JSON 清单」：

- `build.yml`（可复用）：checkout 源码仓库到 `src/` → buildx 构建 → 推送 Docker Hub，标签固定 `latest` + `YYYY.MM.DD`，GHA 缓存按镜像名分 scope。
- `main.yml`（入口）：jq 读 `config/build-list.json` 生成 matrix，逐项调用 `build.yml`；push 触发限制在清单/工作流路径。
- `migrate.yml`（入口）：jq 读 `config/migrate-list.json`，apt 装 skopeo，`skopeo copy --all --authfile` 直连复制，多标签时从首个目标仓库再复制，最后对比源/目标 digest 写入 Summary。

删除：`scripts/filter-compose-services.py`（compose 构建路径）、`dockerfiles/migrate-template.Dockerfile`（FROM 重打标签的迁移 hack）、根目录 `migrate-list.json`（移入 `config/`）、`main.yml` 中大量注释 job 与 `cleanup-workflow-runs` job。

修复的关键缺陷：
1. 旧 `build.yml` 声明了 `dockerfile_path` / `context_path` 但未使用，context 恒为 `./target-repo`。
2. 旧迁移用 `FROM ${SRC_IMG}` 重建，丢多架构 manifest；`build_arg` 借道 `additional_files_to_copy` 且只取 `[0]`。
3. `skopeo copy` 默认只复制当前架构，必须加 `--all`。

校验方式：PyYAML 解析三份 YAML、`bash -n` 检查所有 run 脚本、python-jq 库验证矩阵过滤表达式、假 skopeo/docker 演练步骤（含多标签与凭据缺失失败路径）。

- 摘要：`## 构建完成` / `## 迁移完成` 两张中文表格，含镜像地址 + Docker Hub 页面链接 + GHCR 包页面链接（`https://github.com/<repo>/pkgs/container/<image>`）。
- README 同步：GHCR 前置条件（GITHUB_TOKEN、Workflow permissions、包默认私有、路径小写）、标签示例、权限与摘要说明。

## 修复三个摘要/定时问题

1. **定时任务漏了迁移**：`migrate.yml` 加 `workflow_call`（声明 DOCKERHUB_* secrets），去掉它自己的 cron；`schedule.yml` 新增 `migrate` job 调用它，与 `build` 并行。现在只有一个定时入口（UTC 04:00），不会一天跑两遍。
2. **摘要里用户名变 `***`**：原因是 metadata `images` 与摘要里引用了 `secrets.DOCKERHUB_USERNAME`，GitHub 会把 secret 取值在日志/摘要中外星成掩码。改为工作流级 `env: HUB_OWNER / GHCR_OWNER: formattoday`，不再引用 secret。**同理，任何要出现在摘要里的值都不能来自 secrets。**
3. **英文摘要残留**：`docker/build-push-action` 默认生成英文 Job Summary，用 `env: DOCKER_BUILD_SUMMARY: "false"` 关闭（注意要加引号，避免被当成布尔）。
4. **链接全指向 latest**：Docker Hub 用 `/r/<repo>/tags?name=<tag>`；GHCR 的 tag 精确链接必须带包版本 ID `.../pkgs/container/<镜像>/<id>?tag=<tag>`，只加 `?tag=` 无效。版本 ID 通过 `api.github.com/{orgs|users}/<owner>/packages/container/<image>/versions` 查询并按 `metadata.container.tags` 匹配，查不到降级为包页面。摘要改成按标签逐行给出两个仓库的直达链接。
